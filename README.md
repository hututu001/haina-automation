# 海纳百川自动化 · 使用与部署说明

适用站点：海纳百川 `https://www.0809.one`（签到 / 抽奖）+ 百川农场 `https://farm.0809.one`（种菜收菜）

三种运行方式任选（也可组合），核心逻辑都在 `haina.py`，完全通用：

- **本地网页控制台**（`haina_server.py`）——在自己电脑上跑，网页点按钮 + 内置定时，不依赖青龙
- **服务器部署**（`haina_server.py` + `deploy/`）——网页控制台原样搬到 Linux 服务器，systemd 常驻 + HTTPS 域名访问，7x24 最省心
- **青龙面板**（`ql_haina.sh` + `haina.py`）——挂在已有青龙上定时

只用 Python 标准库，**无需 pip 安装任何依赖**；账号密码只通过配置或环境变量传入，不写死在代码里。

## 一、文件清单

| 文件 | 作用 |
|---|---|
| `haina.py` | 统一主程序，4 个子命令：`signin`（签到）/ `draw`（抽奖）/ `farm`（农场）/ `status`（只读总览）。所有运行方式的公共核心 |

| `启动控制台.bat` | Windows 双击启动网页控制台（可选） |
| `ql_haina.sh` | 青龙任务入口（可选，青龙部署用）：source 青龙 env.sh / config.sh 后调起 `haina.py` |

| `README.md` | 本说明 |

| `data/` | 会话缓存 + 仪表盘摘要 `last_summary.json`（自动生成，迁移不用重新登录） |

## 二、每个功能到底做什么

### 签到（signin）

固定流程：查今日 token 消耗 → 达标（≥100 万 tokens）才钱包签到 → 领取**所有**当前可领的活动福利（含签到抽奖机会）。

- 没到 100 万门槛：跳过钱包签到，只提示差多少；福利照领
- 已领过的不会重复领（重复执行安全）
- 时段福利（早/午/晚）现在脚本自动检测状态，能领就领、过期就跳过
- 开了「签到后自动抽奖」（网页设置）会在领完福利后**接着把奖抽了**，见下方抽奖章节

示例日志：

```
[*] 正在认证（优先复用缓存会话）…
[OK] 已复用缓存 Token uid=****，未重新登录
[*] 正在查询今日 token 消耗…
     今日 tokens: 363,647 (prompt 359,522 + completion 4,125)
[!]  钱包签到跳过 (差 636,353 tokens)
[*] 正在获取抽奖面板…
     签到福利: 已用
[-]  当前无可领取的福利
```

### 抽奖（draw）

先显示余额 / 可抽次数 / 奖池，再抽并显示奖品。次数不足时只报状态不抽。**抽多少由「抽光模式」决定**（网页设置里切换，按钮文字跟随变化）：

- **抽光模式关**（默认）：只抽 1 次，保守留次数
- **抽光模式开**：把当前可抽次数**一次抽完**，每抽间隔 0.5 秒，抽完出汇总

示例日志（抽光模式）：

```
[*] 开始抽奖 (3 次, 抽光模式)...
  +-- 第 1 抽 -------------------------
  | 小额额度丙 [COMMON]
  | 额度: +5
...
  抽了 3 次
  汇总:
    小额额度丙: x3
  总额度: +15
```

命令行等价：`python haina.py draw --all`（或环境变量 `HAINA_DRAW_ALL=1`）。

### 签到（signin）的自动抽奖

设置里开了「**签到后自动抽奖**」，签到流程就变成：查消耗 → 钱包签到 → 领完所有福利 → **紧接着把可抽的奖全抽了**（次数遵循抽光设置：开=抽光，关=只抽 1 次），一个按钮一条龙。命令行等价 `python haina.py signin --draw [--draw-all]`。

### 农场（farm）——重点说明

完整流程：**状态 → 一键收菜 → 自动补种 → 兑换**（偷菜需显式开启）。每一步的行为：

**1. 一键收菜**：只收「已成熟」的地块，生长中的不动。收获的额度先进「待兑换」。

**2. 自动补种**——会自己买种子，规则如下：

- 只补「空闲」地块，锁定 / 生长中的不会被动
- 种什么：默认选**当前周消费等级能种里、时薪最高的**作物（Lv.1 = 小麦/玉米里选玉米；周消费升到 Lv.2 会自动改种番茄）。可在设置里用 cropId 指定
- 种子从哪来：**库存优先**——先用已有的种子库存；不够的部分**自动购买**，一粒一粒原子「买+播」
- 买之前校验主站余额：余额不足就整块跳过补种并提示（不会把余额买爆）
- 示例日志：

```
[补种]
[*]  补种 🌽 金穗玉米 x6 (库存 0，需买 6 粒 = 1.200 额度)
[OK] #0 购买并播种 金穗玉米
[OK] #1 购买并播种 金穗玉米
...
[*]  补种完成 6/6
```

**3. 兑换**：把待兑换额度兑成主站余额。受**本周消耗 × 40% 上限**约束（每周一重置，不跨周结转）。「本周已用完」属正常状态，只提示不报错。

**4. 偷菜（默认关，需手动开启）**：3 体力/次。脚本自动翻页扫描全服玩家目录（每页有进度显示），找「成熟且未被偷满 3 次」的地块按可偷数从多到少偷。实测成熟作物竞争激烈，大多数时候扫完 7 页都是 0 个目标——这是服务器的真实竞争情况，不是卡住。

### 状态总览（status）

只读，抽奖面板 + 农场一次看全，不做任何写操作，随时可点，也用于排查问题。

### 怎么判断「正在运行」还是「卡死」

- 网页控制台：任务栏显示**运行中 + 已运行秒数**（实时跳动），日志区从「[控制台] 开始…」起逐行滚动，每个网络阶段都有 `[*] 正在…` 提示
- 每个任务有 **15 分钟看门狗**：万一真卡住会自动强制收尾、解锁控制台并明确标注，不会再出现永远「正在运行」
- 各任务正常耗时参考：签到 10~25 秒、状态总览 10~25 秒、农场 30~60 秒、农场+偷菜再加 10~60 秒

## 三、方式 A：本地网页控制台

### 启动与登录

双击 `启动控制台.bat`（保持黑色控制台窗口开着，关掉它服务就停），浏览器自动打开 `http://127.0.0.1:8787`（端口占用会自动顺延）。

首次打开，页面顶部是「登录海纳百川」卡片：填邮箱密码点「登录并保存凭证」——凭证存到本机 `haina_web.json`，同时立刻跑一次登录验证（约 10~20 秒，日志实时显示）。成功后卡片自动隐藏；换号 / 改密时展开底部「⚙ 设置」。

### 定时规则：怎么看、怎么改

主页「定时」卡片直接展示全部规则和今日执行状态：

```
签到   每天 00:10        今日已跑 ✓
农场   每天 06:00 / 14:00 / 22:00   今日 14:00 已跑 ✓
抽奖   仅手动            按需点击
接下来：08-28 22:00 农场　08-29 00:10 签到　…
```

点「✎ 修改定时规则」直达设置，**所有时间都可以自己手写**：

- 签到时间：一个 `HH:MM`
- 农场时间：逗号分隔任意多个，如 `06:00,14:00,22:00`（想 4 小时一收就写 `06:00,10:00,14:00,18:00,22:00`）
- 抽奖时间：默认留空 = 仅手动；填了时间到点自动抽（次数遵循抽光设置：开 = 抽光，关 = 只抽 1 次）
- 格式：24 小时制 `HH:MM`，也接受 `H:M`、中文冒号；改完保存立即生效，无需重启

补跑机制：定时靠本机时钟，**电脑关机期间不执行**；开机后服务启动 15 秒内自动补跑当天错过的任务（签到当天没跑过就补一次，农场补最近错过的时段），已跑过的当天不会重复。

### 仪表盘 / 运行历史 / 日志浏览器

- **仪表盘**：页面顶部 5 张卡片（主站余额 / 待兑换额度 / 可抽次数 / 地块 / 体力），每次任务跑完自动刷新
- **最近 API 调用**：站点使用日志里最近 20 条模型调用明细（时间 / 模型 / 输入 / 输出 tokens / 消耗额度 / 耗时），每分钟自动刷新，也可手动刷新。只读复用缓存会话；会话过期时卡片会出现「跑一次状态总览刷新会话」按钮，点一下即恢复
- **运行历史**：列表点击回看输出。最近会话的记录实时滚动；服务重启后自动从 `logs/` 回载（不丢了）
- **日志浏览器**：「日志文件」卡片列出 `logs/` 下全部文件，点击即查看（只读，支持手机上看）。正在浏览文件时不会被新任务输出打断；点任意历史记录或启动任务即切回

### 任务完成推送（可选）

设置里「任务完成后推送」三种模式：

- **关闭**（默认）
- **Webhook**：通用 HTTP 推送，按 URL 自动识别渠道，填一个地址即可：
  - Bark：`https://api.day.app/你的Key`
  - Server酱：`https://sctapi.ftqq.com/你的SendKey.send`
  - Telegram Bot：`https://api.telegram.org/bot你的Token/send`（需能访问 TG 的网络环境）
  - 钉钉机器人 / 飞书机器人 / 企业微信机器人：填各自机器人的 webhook 地址
  - 其他任意地址：按通用 JSON POST `{title, content}`
  - 推送时机可选「仅失败时」（推荐，平时不打扰）或「每次都推」；填完点「发条测试」验证
- **青龙 sendNotify**：本机有青龙环境时用其配置的渠道

### 手机 / 其他电脑访问（可选）

```
python haina_server.py --host 0.0.0.0
```

启动时会打印访问令牌，用 `http://<电脑IP>:8787/?token=xxx` 打开（令牌即密码）。不加 `--host` 时只监听本机。局域网访问首次可能要放行 Windows 防火墙弹窗。

> 需要 7x24 稳定定时就选方式 C（服务器部署，本控制台原样搬上去）或方式 B（青龙）。几种方式可以同时装，但**定时只开一边**（都开会同刻跑两遍；有幂等键不会出错，只是日志混乱）。

## 四、方式 B：青龙面板部署

### 步骤 1：上传

`haina.py` + `ql_haina.sh` 传到青龙「脚本管理」。本机青龙的实际脚本目录：

```
/app/user-packages/node/lib/node_modules/@whyour/qinglong/data/scripts/
```

（从旧版 6 文件升级：删掉旧的 `ql_signin.py`、`haina_draw.py`、`haina_farm.py` 和三个旧 `.sh`，会话缓存路径格式没变，无需重新登录。）

### 步骤 2：环境变量（青龙「环境变量」页面）

| 变量名 | 必填 | 说明 |
|---|---|---|
| `HAINA_USERNAME` | ✅ | 登录邮箱 |
| `HAINA_PASSWORD` | ✅ | 登录密码 |
| `HAINA_NOTIFY` | 否 | 推送开关，默认开；`0` 关闭 |
| `HAINA_FARM_CROP` | 否 | 默认补种作物 cropId（如 `crop_corn`）；不设自动选时薪最高 |
| `HAINA_DRAW_ALL` | 否 | `1` = 抽奖抽光模式（默认只抽 1 次） |
| `HAINA_SIGNIN_DRAW` | 否 | `1` = 签到领完福利后自动抽奖 |
| `HAINA_SESSION_FILE` | 否 | www 会话缓存，默认 `/ql/data/config/haina_session.json` |
| `HAINA_FARM_SESSION_FILE` | 否 | 农场会话缓存，默认 `/ql/data/config/haina_farm_session.json` |
| `HAINA_BASE_URL` / `HAINA_FARM_URL` | 否 | 站点地址覆盖 |

### 步骤 3：定时任务与 cron 写法

默认三件套（命令 = 「命令」栏填的，定时规则 = 「定时规则」栏）：

| 任务名称 | 命令 | 定时规则 | 状态 |
|---|---|---|---|
| 海纳百川·签到 | `bash ql_haina.sh signin` | `10 0 * * *` | 启用 |
| 海纳百川·农场 | `bash ql_haina.sh farm` | `0 6,14,22 * * *` | 启用 |
| 海纳百川·抽奖 | `bash ql_haina.sh draw` | （不设定时） | **禁用**，想抽时手动运行 |

**cron 规则怎么自己写**——五个字段从左到右：

```
分  时  日  月  周
*   *   *   *   *
```

- 每个字段：`*` = 任意，`5` = 具体值，`6,14,22` = 列表，`*/2` = 每隔 2，`1-5` = 范围
- 例子：

| 想要的效果 | 写法 |
|---|---|
| 每天 00:10 签到 | `10 0 * * *` |
| 每天 6/14/22 点农场（玉米 8 小时一熟的节奏） | `0 6,14,22 * * *` |
| 每 4 小时收一次（更高频） | `0 */4 * * *` |
| 每天中午 12:30 也抽一次奖 | `30 12 * * *`（命令用 `bash ql_haina.sh draw`，任务启用） |
| 只在工作日跑（周六日不跑） | `0 6,14,22 * * 1-5` |
| 偷菜版农场 | 命令改为 `bash ql_haina.sh farm --steal` |

常用命令一览（青龙手动运行或命令行都可用）：

```
bash ql_haina.sh signin            # 签到
bash ql_haina.sh signin --draw --draw-all   # 签到 + 抽光全部次数
bash ql_haina.sh draw              # 抽 1 次
bash ql_haina.sh draw --all        # 抽光全部次数
bash ql_haina.sh farm              # 农场收补兑
bash ql_haina.sh farm --steal      # 农场收补兑 + 偷菜
bash ql_haina.sh farm --no-plant   # 只收菜不补种
bash ql_haina.sh farm --crop crop_corn   # 指定补种作物
bash ql_haina.sh status            # 只读总览（排查用）
```

青龙里跑的是子进程（`python3 -u`，已关缓冲），日志页逐行实时刷新，和网页控制台看到的一致。

## 五、方式 C：服务器部署（systemd + HTTPS，推荐 7x24 方案）

把网页控制台整包搬到任意 Linux 服务器（有 python3 ≥ 3.8 即可，无需 pip）。本地怎么用，服务器上就怎么用——网页操作、定时、仪表盘、日志、推送全部一样，且**重启不丢历史**。

### 步骤 1：上传文件

只需要 3 个文件（其余自动生成）：

```
/opt/haina/
├── haina.py
├── haina_server.py
├── web/               # 新版前端（index.html + app.js + style.css，整个目录一起传）
└── deploy/            # 可选，两个配置模板
    ├── haina-web.service
    └── nginx-haina.conf
```

```bash
sudo mkdir -p /opt/haina
# scp / sftp 上传后：
sudo cp deploy/haina-web.service /etc/systemd/system/
```

> 从本地电脑整体搬家：把本地 `data/` 一起拷过去可以**免重新登录**（会话缓存直接续用）。

### 步骤 2：启动 systemd 服务

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now haina-web
systemctl status haina-web      # 应显示 active (running)
journalctl -u haina-web -n 20   # 看启动日志（含访问令牌）
```

服务特性：开机自启、崩溃 5 秒自动拉起、日志进 journal。定时规则、账号、推送都在**网页设置里改**，改完即生效，不用碰命令行。

### 步骤 3：HTTPS 域名访问（nginx 反代）

控制台默认只监听 `127.0.0.1:8787`，由同机 nginx 反代成 HTTPS 域名（配置模板 `deploy/nginx-haina.conf`，含 acme.sh 签证书步骤）：

```bash
# 域名 DNS A 记录 → 服务器 IP 后：
sudo cp deploy/nginx-haina.conf /etc/nginx/conf.d/haina.conf
# 编辑：改 server_name 和证书路径，然后：
sudo nginx -t && sudo nginx -s reload
```

**上 HTTPS 后必须做的一件事**：网页「设置」里勾选「**信任反代 IP**」。

> 原理：nginx 同机回源时控制台看到的来源 IP 是 127.0.0.1，会被当成"本机访问"而跳过令牌校验。勾选信任反代后改按 `X-Real-IP`（nginx 每次覆盖写入，访客无法伪造）判定，远程访客必须带令牌。不勾 = 任何知道域名的人都能进你的控制台。

首次访问 `https://你的域名/?token=xxx`（令牌看 `journalctl -u haina-web` 启动输出，或 `cat /opt/haina/haina_web.json` 里的 `token` 字段），之后浏览器记住 cookie 不用再输。

### 步骤 4（可选）：任务推送

服务器上没人盯着网页，建议配上推送：网页「设置」→ 推送方式选 **Webhook** → 填 Bark / Server酱 / TG Bot / 钉钉等地址 → 推送时机选「仅失败时」→ 点「发条测试」。之后定时任务跑挂了手机立刻收到通知。

### 不想配域名？两个替代方案

1. **IP + 令牌直连**：网页设置「监听地址」填 `0.0.0.0`（或命令行 `--host 0.0.0.0`），防火墙/安全组放行 8787，用 `http://服务器IP:8787/?token=xxx` 访问。有令牌校验但没有 HTTPS，密码明文过公网，仅建议临时用
2. **SSH 隧道**（零暴露，最安全）：本地 `ssh -L 8787:127.0.0.1:8787 root@服务器`，然后本机开 `http://127.0.0.1:8787`。不对外开放任何端口

### 安全机制一览

| 机制 | 说明 |
|---|---|
| 令牌校验 | 非本机访问必须带 token（URL 换 cookie），令牌在 haina_web.json |
| 登录防爆破 | 保存凭证的登录接口每 IP 10 分钟最多 10 次，超了返回 429 |
| 路径穿越防护 | 日志接口只允许读 `logs/` 目录内的 `.log` 文件 |
| 看门狗 | 任务 15 分钟未结束强制收尾解锁，服务不会假死 |
| 会话优先 | 密码只在缓存全失效时使用，正常几周不登录一次 |

### 日常运维

```bash
systemctl restart haina-web    # 重启（改 haina.py 代码后需要）
journalctl -u haina-web -f     # 实时日志
journalctl -u haina-web --since today   # 今天的日志
ls /opt/haina/logs/            # 任务日志文件（网页里也能看）
```

升级：覆盖 `/opt/haina/haina.py`、`haina_server.py` 和 `web/` 目录后 `systemctl restart haina-web`。`haina_web.json`、`data/`、`logs/` 都在原地，配置和历史不受影响。（`web/` 目录忘了传也能跑，控制台会自动回退到内置旧版页面。）

## 六、会话缓存机制（为什么基本不会碰密码）

**优先复用已有会话，密码登录只是最后兜底**，避免频繁登录触发站点限制：

1. **签到 / 抽奖**：缓存 lottery token 有效 → 直接用；access token 过期用 refresh cookie 轮换 → 都失效才密码登录
2. **农场**：农场 cookie 有效 → 直接用；失效则用 www 会话走 SSO 换新农场会话；www 会话也失效才密码登录
3. **status**：两套认证各走各的

缓存文件：网页控制台默认存 `data/`，青龙默认存 `/ql/data/config/`；格式相同，迁移不用重新登录。写缓存带文件锁 + 原子替换，并发安全。

## 七、农场玩法速查（脚本决策依据）

- **经济换算**：1 显示额度 = 500,000 quota。种子钱从主站余额扣；收获先进「待兑换」，兑换后才进主站余额
- **周兑换上限** = 本周主站实际消耗 × 40%，每周一 00:00 重置，不跨周结转
- **作物解锁看周消费等级**（weeklyLevel），不是经验等级。Lv.1 只能种小麦 / 玉米；周消耗到 450 升 Lv.2 解锁番茄
- **地块数量随周消耗提升**（6 → 8 块需周消耗 450）
- **作物时薪**（显示额度/小时）：Lv.1 小麦 = 玉米 0.475；Lv.2 番茄 0.633；Lv.4 葡萄 0.643。脚本自动选能种里最高的
- **浇水 / 施肥**（露水 / 灵肥）：加速收益低于道具成本，脚本不自动购买
- **偷菜**：3 体力/次，20 分钟回 1 点，每块地最多被偷 3 次；竞争极激烈，默认关闭
- **兑换入账有延迟**：兑换成功后主站余额可能几分钟后才刷新，属正常现象

## 八、常见问题

**Q：点按钮后日志没反应？**

任务栏会立刻显示「正在运行 + 已运行秒数」，日志第一行「[控制台] 开始…」立即出现，之后每个阶段都有 `[*] 正在…` 提示。超过 15 分钟看门狗会强制收尾解锁。若还是异常，重启控制台（关掉黑窗口再双击 `启动控制台.bat`），完整日志在 `logs/` 目录。

**Q：日志报「登录会话已达上限」（AUTH_SESSION_LIMIT）？**

去海纳百川网页端「登录会话」页面撤销旧会话。正常使用（走缓存）几乎不会触发。

**Q：收不到推送？**

网页控制台用 Webhook 模式（设置里填地址后点「发条测试」，页面会显示发送结果和失败原因）。青龙用 sendNotify 的：检查 config.sh 通知渠道是否配置、`HAINA_NOTIFY` 是否为 `0`、日志里有无「青龙通知发送失败」报错。

**Q：农场会话过期了要处理吗？**

不用。脚本自动走 www 会话 SSO 重建，全程无感。

**Q：余额够但补种失败？**

种子按显示额度 × 50 万从主站余额扣；余额 < 种子成本时脚本自动跳过并提示。也可能是站点瞬时错误，重跑一次即可（写操作带幂等键，重复执行安全）。

**Q：网页控制台和青龙同时用？**

手动触发随意；定时只留一边，否则同刻跑两遍。

## 九、脚本行为约定

- 写操作全部带 `Idempotency-Key` 请求头（站点要求），重复执行安全
- `status` 与各子命令 `--status-only` 均为只读，可放心随时跑
- 抽奖默认每次只抽 1 次；「抽光模式」（网页开关 / `--all` / `HAINA_DRAW_ALL=1`）才一次抽完
- 农场补种只动空闲地块；锁定 / 生长中的不会被动
- 会话缓存有效时不配密码也能跑；缓存失效且无密码时明确报错，不会反复重试
- 网页控制台单任务看门狗 15 分钟（`HAINA_WEB_RUN_TIMEOUT` 环境变量可调）
